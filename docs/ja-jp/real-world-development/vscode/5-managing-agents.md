GitHub Copilot をエージェント モードで使うと、コードベースを調べ、変更を提案し、ファイルを編集し、コマンドを自律的に実行します。VS Code の Copilot Chat では、作業が手元でリアルタイムに行われるため、ツールの呼び出しとファイルの編集を逐一確認できます。差分をインラインでレビューし、変更を個別に承認または取り消せます。エディターを離れずに追加のプロンプトを送って、作業を調整・拡張することもできます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- セッションの途中でエージェントに指示し、ハイコントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタムエージェントが、ハイコントラスト モードを実装しています。作業中にデザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じる利用者向けに、ライトモードの切り替えも追加してほしいとのことです。最初から新しい会話を始める代わりに、進行中のセッションに指示を追加して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各ステップが表示されます。調査するファイル、実行するコマンド、提案する編集を確認できます。各ファイルの変更は差分と **Keep** / **Undo** 操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール操作を確認します。ファイルの読み取りや編集、実行の許可を求めるターミナル コマンドなどが表示されます。
3. エージェントがファイル編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択して変更を承認します。
   - **Undo** を選択して変更を取り消し、エージェントに別の方法を試してもらいます。
4. チャット上部の **Files changed** インジケーターを開くと、このセッションで変更されたファイル全体を確認できます。

> [!NOTE]
> ツール操作 (ターミナル コマンドの実行など) の許可を求められると、エージェントは一時停止し **Allow** を表示します。許可するのは、内容を確認して問題ないコマンドだけにしてください。

5. エージェントがハイコントラスト モードの実装を終えるまで待ちます。変更内容をまとめたメッセージが表示されます。

## エージェントにライトモードを追加するよう依頼する

ハイコントラスト モードができたので、同じ会話を続けてライトモードの切り替えを追加します。同じチャット セッションを続けると、エージェントは以前の作業のコンテキストを維持します。変更したコンポーネント、採用したスタイル方法、設定したローカル ストレージのパターンなどが含まれます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは以前の変更を確認し、ライトモードを追加するための変更を提案します。
3. ハイコントラスト モードのときと同じように、新しい編集を確認します。差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが意図しない方法で進める場合 (たとえば、気に入らない方法でトグル UI をリファクタリングしようとする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の説明を送信します。

> [!TIP]
> 進行中のセッションを誘導すると、最初からやり直すより短時間で済みます。追加のプロンプトで変更を依頼したり ("CSS を簡潔にしてください。セレクターを重複させず、CSS 変数を使ってください")、方向を修正したり ("3 つ目のトグルを追加せず、既存の設定パネルにライトモードを組み込んでください")、範囲を広げたり ("両方のトグルにキーボード ショートカットも追加してください") できます。

## 作業内容をレビューする

コミットする前に、エージェントが変更したファイルを確認しましょう。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントによるアクセシビリティ パターンが反映されていることを確認します。ARIA 属性、キーボード操作、セマンティック HTML、ローカル ストレージによる設定の保持などが対象です。
4. 問題がなければ Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使って、進行中のセッションを監視して誘導しました。各ファイルの編集を確認して変更を承認または取り消し、コンテキストを保ったまま追加のプロンプトで作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または取り消しました。
- 追加のプロンプトで、作業中のセッションを誘導しました。
